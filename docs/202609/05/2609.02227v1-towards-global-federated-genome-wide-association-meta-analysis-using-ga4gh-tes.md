## 摘要
全基因组关联研究（GWAS）从大规模、祖先多样化的队列中获得统计效力，但隐私法规和数据驻留限制通常阻止基因组数据跨机构或国家边界进行集中汇总。我们提出了一种基于APPFL框架的隐私保护联邦GWAS荟萃分析流程，其中每个站点计算本地GWAS汇总统计量，仅传输聚合结果，从不传输个体水平基因型。分析通过全球基因组与健康联盟（GA4GH）任务执行服务（TES）端点的全球网络执行，使得计算能够移向数据而非反之。服务器执行逆方差加权固定效应荟萃分析，并将聚合结果返回给所有站点，而我们开发的地理可观测性工具包HiveWatch则提供分布式任务执行的实时监控。在针对2型糖尿病和体重指数的100,000个合成个体及约240,000个变异体的五站点模拟中，联邦荟萃分析再现了预期从汇总分析中获得的关联信号，而无需集中任何基因型数据，表明基于标准的任务执行和联邦学习为国际GWAS荟萃分析提供了实用的隐私保护基础设施。

## Abstract
Genome-wide association studies (GWAS) gain statistical power from large, ancestrally diverse cohorts, but privacy regulations and data-residency constraints often prevent genomic data from being centrally pooled across institutional or national borders. We present a privacy-preserving federated GWAS meta-analysis pipeline built on the APPFL framework, in which each site computes local GWAS summary statistics and transmits only aggregate results, never individual-level genotypes. Analysis is executed through a global network of Global Alliance for Genomics and Health (GA4GH) Task Execution Service (TES) endpoints, which allows computation to move to the data rather than the reverse. The server performs inverse-variance-weighted fixed-effect meta-analysis and returns aggregated results to all sites, while HiveWatch, our developed geographic observability toolkit, provides real-time monitoring of distributed task execution. In a five-site simulation over 100,000 synthetic individuals and roughly 240,000 variants for Type 2 Diabetes and Body Mass Index, the federated meta-analysis reproduces the association signal expected from a pooled analysis without centralizing any genotype data, showing that standards-based task execution and federated learning enables a practical privacy-preserving infrastructure for international GWAS meta-analysis.

## 2. 方法论：核心思想、关键技术细节与算法流程

**核心思想**：采用经典跨孤岛联邦学习（cross-silo FL）模式，以“计算靠近数据”（bring-compute-to-data）的方式，让每个参与站点只输出聚合统计量，而中心服务器只做统计整合，全程不接触任何单一个体数据。

**系统组成（三组件架构）**：

1. **APPFL（Advanced Privacy-Preserving Federated Learning）框架**
   - 负责联邦学习流程的整体编排与聚合。
   - 每个站点实例化 `SiteGWASTrainer`，负责：
     - 加载本地 PLINK 基因型与表型/协变量表；
     - 对数量性状（BMI）执行分块普通最小二乘（OLS）GWAS；
     - 对二元性状（T2D）执行基于逻辑零模型的协变量校正得分检验；
     - 返回每个变异体的**效应量 βᵢ、标准误 SEᵢ、次等位基因频率和样本量**。
   - 服务器端运行 `MetaAnalysisAggregator`，执行**逆方差加权固定效应荟萃分析**。

2. **核心技术公式（逆方差加权固定效应荟萃分析）**

   设第 i 个站点的权重 wᵢ = 1/SEᵢ²，则：

   - 合并效应量：

        β_meta = Σᵢ wᵢ βᵢ / Σᵢ wᵢ

   - 合并标准误：

        SE_meta = 1 / √(Σᵢ wᵢ)

   随后由 Z 统计量推导 p 值。基因组显著性阈值取 p < 5×10⁻⁸。

   - 由于公式（1）只组合传输的聚合数据，联邦估计值在**渐近意义上等价于合并固定效应分析**；若各站点残差方差齐性，则结果完全相同。

3. **GA4GH TES 端点网络**
   - 每个参与方站点部署一个由 **Funnel** 工具实现的 GA4GH TES 端点，运行于不同地理区域的云环境。
   - TES 是 GA4GH 制定的标准化 API，支持在异构计算环境间安全提交、监控和管理任务，实现可移植的“计算到数据”工作流。
   - APPFL 通过标准 TES API 向各站点提交容器化 GWAS 任务，各端点在本地执行，并对请求方进行认证与授权，仅允许可信联邦服务器提交、监控和获取任务结果。

4. **HiveWatch（地理可观测性工具）**
   - 自研开源工具（https://github.com/APPFL/hivewatch），与 APPFL 集成。
   - 记录任务分发、执行、完成事件，并在实时地理地图上可视化，支持事后从日志完整回放，便于诊断异构基础设施中的停滞、掉队和失败节点。

**算法流程（文字描述）**：

1. 各站点在本地启动 TES 端点；
2. APPFL 服务器通过 TES API 向各站点提交容器化的 GWAS 分析任务；
3. 各站点 `SiteGWASTrainer` 执行本地关联分析，获得每个变异体的 βᵢ 与 SEᵢ；
4. 各站点只上传聚合汇总统计数据（效应量、标准误、MAF、样本量）；
5. 服务器执行逆方差加权固定效应荟萃分析，得到全基因组范围的合并 p 值；
6. 服务器将聚合结果返回所有站点；HiveWatch 全程实时监控各端点的任务执行与地理分布状态。
