Abstract —High-dimensional bioinformatics data, character-ized by a large number of features relative to the number of samples, pose major challenges such as the “curse of dimen-sionality,” leading to overfitting, high computational cost, and poor generalization. Traditional feature selection methods often suffer from limited scalability and adaptability in such domains. We propose an LLM-in-the-loop reinforcement learning (RL) framework for bioinformatics feature selection, where the RL agent formulates feature selection as a sequential decision-making task, while the large language model (LLM) enhances the process in two ways: (1) guiding exploration through domain-informed advice, and (2) providing hybrid rewards that integrate data-driven performance with knowledge-driven evaluation. The LLM also produces explanations to improve interpretability for human experts without altering the RL policy update. Experiments on diverse bioinformatics datasets show that the LLM-in-the-loop framework outperforms baselines, achieves stable performance across downstream models, and converges faster than pure RL. 

Keywords —Feature Selection, Large Language Models, Rein-forcement Learning, LLM in the Loop. 

I. I NTRODUCTION 

With advances in data collection, high-dimensional data have become increasingly common and challenging, partic-ularly in bioinformatics [1]. Such datasets often contain tens of thousands of features but only a few hundred samples in practice, giving rise to the well-known “curse of dimensional-ity.” This leads to two major challenges: (1) models are likely to overfit, as noisy correlations can outweigh true biological signals, and (2) computational costs grow rapidly, which makes model training expensive [2]. For example, genomic or molecular datasets may require processing the full set of descriptors, which will slow down both model development and clinical translation. Feature selection is therefore essential to remove irrelevant or redundant features [3]. Beyond reduc-ing complexity, selecting a biologically meaningful feature subset (e.g., key genes or biomarkers) improves predictive performance and enhances interpretability for downstream biomedical analysis and clinical research. Fig. 1 shows how feature selection reduces downstream task processing time while boosting performance on a myocardial infarction dataset. Traditional feature selection approaches fall into three cate-gories: filter, wrapper, and embedded [4]. Filter methods (e.g., Fisher Score [5], Information Gain [6], Chi-Square Test [7]) evaluate features individually before model training. They are 

Fig. 1: Feature selection brings fewer key features to improve downstream performance and reduce processing time. efficient but ignore feature interactions, which often leads to missing informative combinations. Wrapper methods assess subsets using the performance of a predictive model [4]. While typically more accurate, they are expensive for high-dimensional datasets, since a new model must be trained for each subset. Embedded methods integrate selection into model training, such as Lasso regularization [8] and its extensions [9], which enforce sparsity in parameters. These balance efficiency and accuracy, but remain model-dependent and lack generality across domains. Reinforcement Learning (RL) offers a new view on feature selection [10]–[13]. It frames feature selection as a sequential decision process for each feature. An RL agent learns through trial and error to find the best feature subset. Compared to traditional methods, RL can perform a more global search and adapt to changing data environments. RL shows great potential but faces two main challenges. First, exploration within large feature spaces is inefficient. The vast number of possible feature combinations makes a purely “blind” search slow and unlikely to identify the best solution. Second, reward signals are limited by predefined metrics. In RL-based feature selection, rewards are usually derived from human-defined performance metrics, which may not fully capture domain relevance or real-world utility. To address these challenges, we propose an LLM-in-the-loop RL framework that treats LLMs as domain experts to assist the agent. First, LLM as Decision Maker: The LLM uses its extensive domain knowledge, narrows the exploration space by suggesting promising features, and at each step advises whether the current feature should be selected. Second, arXiv:2610.05600v1 [cs.LG] 4 Oct 2026 Fig. 2: Overview of the LLM-in-the-loop reinforcement learning framework for feature selection. LLM as Reviewer: The LLM provides feedback after each decision, producing a hybrid reward that combines the LLM’s knowledge-driven evaluation with the policy’s data-driven per-formance. This mitigates the bias of conventional reward and offers the agent a richer and more realistic learning signal. In addition, the LLM generates natural-language explanations of its advice and reviews, which, while not part of the RL loop, enhance interpretability for human experts. Experiments in bioinformatics domains verify the frame-work. The results show that it achieves the best or second-best performance in most tasks, with improvements of up to 4% in classification accuracy and a lower regression error compared to baselines. In addition, convergence analysis indicates that the LLM-in-the-loop framework achieves comparable perfor-mance more quickly, and ablation results confirm the value of LLM guidance in both decision-making and reward shaping. II. LLM-IN -THE -L OOP RL F RAMEWORK 

A. Background and Task 

Feature selection is important in high-dimensional bioin-formatics tasks, where datasets often contain thousands of candidate features but only limited samples. Using all features may introduce noise and redundancy, increase computational cost, and reduce model interpretability. Let D = ( X, y) denote a supervised dataset, where X ∈

Rn×d contains n samples and d features, and y denotes the labels or regression targets. The goal is to select a compact subset S ⊆ { 1, . . . , d } and train a downstream model on XS ,so that prediction performance is improved while redundancy and complexity are reduced. Feature selection is combinatorial, since the number of possible subsets grows exponentially with d. RL provides a se-quential formulation by deciding whether to select or skip each candidate feature. However, pure RL may explore inefficiently and rely only on task-driven reward signals. We therefore introduce LLM guidance into the RL loop, combining RL-based optimization with LLM-based knowledge about feature relevance, redundancy, and semantic consistency. 

B. Proposed Method 

Our framework integrates three LLM-assisted modules into the RL-based feature selection process: an LLM filter, an LLM decision maker, and an LLM reviewer. The LLM filter first builds a candidate priority list based on feature names, statistical summaries, and available domain descriptions. This step is used to prioritize exploration rather than permanently discard low-ranked features, so the RL agent can still discover useful but non-obvious candidates. As shown in Fig. 2, the RL agent sequentially interacts with the environment. At each step, the agent observes the current selected subset and the current candidate feature. Before making a decision, it queries the LLM decision maker, which outputs an action advice score indicating whether the candidate feature is promising. The RL agent combines this score with its own policy to take an action. After the action is executed, the environment provides downstream validation feedback, and the LLM reviewer provides an additional knowledge-driven evaluation. These signals are combined into a hybrid reward. The LLM does not directly determine the final feature sub-set. Instead, it acts as a soft guide for exploration and reward shaping. The final policy is still learned by the RL agent using task-driven validation feedback. The LLM also produces short natural-language explanations for human interpretability, but these explanations are not used in policy updates.

A. Experimental Setup 

Dataset: We evaluate on diverse datasets from bioinformatics, healthcare, and scientific domains, covering both classification and regression tasks (Table I). All datasets are publicly avail-able without any identifiable personal information. Experimental Environment: Experiments were conducted on Ubuntu 22.04.3 with an Intel i9-13900KF CPU, Python 3.11.5, PyTorch 2.0.1, and an NVIDIA RTX 4090 GPU. Evaluation Metrics: For classification tasks, we report accu-racy, and for regression tasks, we use the ℓ2 error. Baseline Algorithms: We compare methods from five cate-gories: embedded (LASSO [8], RFE [14]), filter (KBest [5], mRMR [15]), evolutionary (MCDM [16]), neural (STG [17], FSNS [18]), and RL (MARLFS [12], SADRLFS [11]). LLM Configuration and Prompt: We use GPT-4o as the backbone with a fixed prompt template (Fig. 3). The LLM is used only for feature-level advice and intrinsic feedback; it does not directly determine the final selected subset. All LLM outputs are constrained to a numerical score, an uncertainty flag, and a short explanation.

C. Ablation Study 

We test the effect of each LLM module by removing them in turn: (i) without the Decision Maker, (ii) without the Reviewer, and (iii) without both (pure RL). Table I shows that all three cases reduce performance. The drop tends to be larger when both modules are removed. Without the LLM Decision Maker, the RL agent explores slowly and may miss good features. Without the LLM Re-viewer, the reward only relies on human-defined metrics, which can be narrow or biased. Pure RL performs worst, especially in high-dimensional data. Even partial use of LLM gives a gain, which means the two modules bring different but useful effects. Insight: The Decision Maker improves exploration by fo-cusing on semantically relevant features, while the Reviewer refines the reward with domain-informed feedback. Together, they enable faster convergence and more accurate selection.

To further evaluate stability, we examine whether the pro-posed framework maintains consistent performance across different downstream models.

E. Convergence Analysis 

To examine whether the integration of LLM guidance improves convergence efficiency compared with pure RL, we compared the run time for each round and the whole process. 

(a) Run Time per Step (b) Total Run Time 

Fig. 5: Results on convergence efficiency. Fig. 5 reports the convergence efficiency results. As shown in Fig. 5a, introducing LLM guidance increases the run time of each decision step because the agent needs additional LLM inference for action advice and reward feedback. However, Fig. 5b shows that the proposed LLM-in-the-loop framework achieves a lower total run time than the value-based RL baseline. This is because the LLM-guided agent converges with fewer exploration steps, reducing repeated trials over uninformative or redundant features. Therefore, although LLM involvement brings extra per-step overhead, it improves the overall search efficiency of the RL process. Insight: The convergence results reveal a useful trade-off between local computation cost and global optimization effi-ciency. Pure RL relies mainly on trial-and-error exploration, which can be inefficient in high-dimensional feature spaces. In contrast, our design uses the LLM decision maker to guide exploration toward semantically promising features and the LLM reviewer to provide richer reward feedback after each action. These two modules reduce blind exploration and help the agent reach a high-quality feature subset faster. Thus, the added LLM cost is compensated by more efficient policy learning and faster convergence. 

F. Reliability of LLM Guidance 

Since LLM outputs may be uncertain or inconsistent, we do not treat the LLM as an oracle. The LLM only provides auxil-iary advice and intrinsic reward signals, while the final policy is still optimized using validation-based extrinsic rewards. To reduce hallucination risk, we use constrained prompts, fixed output formats, uncertainty flags, and consistency checks. If the LLM advice repeatedly conflicts with validation feedback, its influence is reduced by lowering the policy-bias weight 

α or increasing the extrinsic-reward weight λ. This design makes the framework robust to imperfect LLM knowledge and prevents the feature selection process from being fully controlled by the LLM. IV. C ONCLUSION 

We presented an LLM-in-the-loop RL framework for feature selection, where the LLM acts as both a decision maker and a reviewer. These two roles address the key challenges of RL-based feature selection: inefficient exploration and biased re-ward signals. In addition, the LLM provides natural-language explanations of its advice and feedback, improving trans-parency and supporting human interpretability. Experiments on diverse bioinformatics datasets show that the LLM-in-the-loop framework outperforms baselines, achieves stable results across different downstream models, and converges faster despite the extra cost of LLM inference in high-dimensional feature selection.
