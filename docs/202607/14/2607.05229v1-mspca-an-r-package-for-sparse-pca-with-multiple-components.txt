Abstract 

We present msPCA : an open-source R package for sparse principal component analysis with multiple components. It implements an alternating maximization algorithm to generate a set of sparse loading vectors that collectively explain a large fraction of the variance in a dataset, while remaining non-redundant. The algorithm supports two definitions of non-redundancy: either orthogonality of the loading vectors or zero pairwise correlation between principal components (PCs). In the reported benchmarks, msPCA solves sparse PCA problems with thousands of features, achieving competitive runtimes while producing sparse components with controlled feasibility violations and a high fraction of variance explained. 

Keywords: principal component analysis, sparsity, multiple components, msPCA, Rcpp, R

1 Introduction 

Principal component analysis (PCA; Pearson, 1901; Hotelling, 1933) reduces a p-dimensional dataset to r dimensions by projecting onto the leading eigenvectors of the empirical covari-ance matrix Σ. Effectively, each coordinate in the compressed dataset can be expressed as a linear combination of the original variables. Beyond interpretability challenges, sam-ple eigenvectors from dense PCA can be inconsistent in high-dimensional regimes when 

p/n → α > 0 (Johnstone and Lu, 2009; Deshpande and Montanari, 2016), and including every feature in every component complicates downstream analysis (Rudin et al., 2022). Sparse PCA addresses both issues by constraining each loading vector to contain at most kt

nonzero entries. The single-component case is well-studied (d’Aspremont et al., 2007; Yuan and Zhang, 2013; Bertsimas et al., 2022); we focus on the substantially harder r-component case, for which guaranteeing non-redundancy across loading vectors is the central challenge. We refer to Bertsimas et al. (2022) and Cory-Wright and Pauphilet (2026) for comprehensive reviews of the single- and multiple-component cases, respectively. The package msPCA implements a Lagrangian alternating maximization algorithm for sparse PCA with r > 1 components, similar to the one proposed by Cory-Wright and Pauphilet (2026). The algorithm attaches penalty parameters to the coupling constraints and progressively increases them until feasibility is attained or the iteration budget is

Regarding sparsity, msPCA allows the user to specify a hard sparsity constraint on each loading vector (of the form ∥ut∥0 ≤ kt), which is fairly common across existing packages. Many packages whose algorithms induce sparsity by introducing an ℓ1 penalty in the objec-tive, such as elasticnet (Zou et al., 2006) or mixOmics (Shen and Huang, 2008; Rohart et al., 2017), still allow the user to express their requirements in terms of cardinality constraints and automatically calibrate the ℓ1 penalty accordingly. The key distinguishing property of 

msPCA relates to how overlapping or redundant PCs are discouraged, as summarized in Ta-ble 1. First, among the R packages considered here, msPCA is the only package to support both definitions, namely imposing orthogonal loading vectors or uncorrelated PCs. Second, among these packages, msPCA is the only method that provides the user with an explicit control parameter η over the violation of these constraints. Some of the algorithms, such as 

elasticnet and sparsepca (Erichson et al., 2020), internally involve projections onto the set of orthogonal matrices, but these projections are not applied directly to the matrix of load-ing vectors. The approaches in PMA (Witten et al., 2009; Witten and Tibshirani, 2009), 

mixOmics (Rohart et al., 2017), nsprcomp (Sigg and Buhmann, 2008; Sigg, 2019), and 

amanpg apply update (or deflation) rules that guarantee orthogonality in the case of dense PCA but have no guarantees in the sparse PCA case. In contrast, the alternating maximiza-tion algorithm in msPCA assigns an increasing penalty on orthogonality/uncorrelatedness violation, theoretically ensuring asymptotic feasibility when subproblems are solved exactly (see Cory-Wright and Pauphilet, 2026, Section 3).

2.1 Problem formulation 

The goal of sparse PCA is to identify r loading vectors u1, . . . , ur ∈ Rp that collectively explain a large share of the variance in the data, while each vector involves only a small number of the p original features. In the single-component case ( r = 1), this corresponds to solving max

In standard (dense) PCA, non-redundancy is ensured by requiring the r leading eigenvectors of Σ to be mutually orthogonal and their projections to be uncorrelated — two properties that hold simultaneously for eigenvectors but generally cannot both be enforced in the sparse setting. Termination. Algorithm 1 stops when (i) the number of outer iterations reaches

Feasibility tracking. At each iteration, Algorithm 1 checks whether the current solu-tion satisfies the coupling constraint up to the tolerance feasibilityTolerance (default: 10 −4). The best feasible solution encountered across all iterations is returned. If no feasible solution is found within the iteration budget, the algorithm returns the solution with the smallest observed constraint violation.

4.3 Diagnostic functions 

The package msPCA provides a set of built-in diagnostic functions for evaluating and dis-playing sparse PCA solutions. These are useful for assessing solution quality and for com-paring against solutions from other packages. 

• fraction variance explained(C, U) : combined FVE of the loading matrix U, as a fraction of tr( Σ). 

• fraction variance explained perPC(C, U) : vector of per-component FVE values. 

• variance explained perPC(C, U) : vector of per-component variance explained (un-normalized). 

• feasibility violation off(C, U, feasibilityConstraintType) : absolute feasi-bility violation, viol off (C, U ) with C = I if feasibilityConstraintType=0 and 

C = Σ if feasibilityConstraintType=1 .

• print(sol, C) : S3 print method for objects of class "mspca" . Displays the sparse loading matrix restricted to variables active in at least one component, together with the percentage of variance explained and the number of nonzero loadings per compo-nent. When the model was fit with type = "X" , C may be omitted and the figures stored inside the result object are used directly. 

• summary(sol, C, feasibilityConstraintType) : S3 summary method. Prints a per-PC statistics table (number of nonzero loadings, variance explained, FVE, and cumulative FVE), the upper-triangular pairwise feasibility violation matrix, and the total solver runtime. Like print() , C may be omitted for type = "X" results.

4.5 Guidance on parameter choices Choosing the sparsity budgets ks . The budgets k1, . . . , k r are the primary tuning parameters. A practical approach is to run mspca() for a range of values and plot the trade-off between FVE (via fraction variance explained() ) and sparsity. Domain knowledge often provides a natural guide: if each PC is expected to represent a distinct thematic cluster of features, setting kt to the anticipated cluster size is a good starting point. 

Choosing the constraint type. Orthogonality ( feasibilityConstraintType = 0 ) is appropriate when the loading vectors are to be used as a projection basis, or when the geo-metric structure of the components matters. Zero pairwise correlation ( feasibilityConstraintType = 1 ) is preferable when the primary goal is statistical decorrelation of the projected data. In our experience, the two options yield similar results when Σ is close to the identity but can differ noticeably for strongly correlated datasets. Section 5 illustrates both options on financial return data. 

5 Case study: factor analysis of S&P 500 returns 

5.1 Data and preprocessing 

We illustrate msPCA on daily returns of S&P 500 constituent stocks, made available under a CC0 1.0 license 1. The code and data for this case study are available in the replication package. The dataset comprises p = 423 stocks for which complete price histories are available over the period January 2010 to December 2019, yielding n = 2 ,515 trading days. 6.1 Implementation of each method 

Comparing sparse PCA methods is complicated because different packages parameterize sparsity differently. Some methods accept a covariance/correlation matrix Σ, others apply only to the data matrix X, and some support both. We detail our implementation of each method: 

• msPCA : We use mspca() with both type = "Sigma" and type = "X" on all four datasets. On the riboflavin dataset ( n ≪ p), the p × p covariance matrix is rank-deficient, making type = "X" the natural choice; we nonetheless report results for both modes to quantify the runtime gain. 

• elasticnet : We use the spca() function, which takes a list of cardinality budgets (one per PC) as input, and can be applied interchangeably to Σ or X. We report results for both input modes on the mtcars, Pitprops, and breast cancer datasets. 

• PMA : We use the SPC() function with the orth=TRUE option, which implements the method of Witten et al. (2009). It takes as inputs the covariance matrix Σ and a bound on Prt=1 ∥ut∥1, sumabsv , which we manually tune for each dataset to achieve a per-component sparsity as close as possible to the desired one. 

• sparsepca : We use the function spca() applied to Σ, which only allows us to control the magnitude of the ℓ1 penalty parameter, alpha . We manually tune this parameter for each dataset to achieve a total sparsity Prt=1 kt as close as possible to the desired one 2.

• mixOmics : We use the spca() function, which takes as input the data matrix X and the list of sparsity budgets. 

• nsprcomp : The package provides two functions nsprcomp() and nscumcomp() . Both rely on the expectation-maximization algorithm of Sigg and Buhmann (2008). The function nsprcomp() uses this algorithm to compute the leading sparse PC and then applies the deflation procedure of Mackey (2008) to compute the subsequent PCs. It applies to the data matrix X and takes as input the list of sparsity levels. The function nscumcomp() applies expectation-maximization to simultaneously solve for the r PCs. It takes as input the total sparsity budget Prt=1 kt and a penalty parameter 

γ on orthogonality violation (default γ = 0).

7 Conclusion 

The package msPCA implements and extends an algorithm for sparse PCA with r > 1components proposed in Cory-Wright and Pauphilet (2026), whose main design feature is that the coupling constraints are explicitly modeled and penalized rather than handled heuristically. The Lagrangian alternating maximization algorithm resembles an iterative deflation procedure where the deflation step depends on increasing penalty parameters that progressively drive constraint violations toward zero across iterations, yielding loading matrices that are simultaneously sparse, high-variance, and designed to be non-redundant. A distinguishing feature is the support for two notions of non-redundancy. Orthogonality (u⊤ 

> t

ut′ = 0) is appropriate when loading vectors serve as a projection basis; zero pairwise correlation ( u⊤ 

> t

Σ ut′ = 0) is preferable when the goal is to obtain statistically uncorrelated scores. The S&P 500 case study illustrates that the two constraints can yield meaningfully different factor compositions on strongly correlated data, and msPCA allows the user to choose explicitly based on their use case rather than relying on an implicit approximation. The package has several limitations that point to future work. First, because of the heuristic nature of the penalty increase scheme, a small fraction of runs may fail to find a feasible solution, though feasibility tracking mitigates this in practice. Second, the package does not yet support online or streaming settings where observations arrive sequentially. Future extensions could include robust covariance variants for outlier-contaminated data and a streaming update scheme for sequentially arriving observations. The package msPCA and its vignette are available at https://CRAN.R-project.org/ package=msPCA . All scripts and data required to reproduce the examples, figures, and tables are provided in the replication materials.
